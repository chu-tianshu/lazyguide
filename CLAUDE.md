# LazyGuide: notes for Claude

- **Ship workflow:** after finishing a change, commit and push to `origin/main` without asking. Vercel deploys every push to `main`. Then tell the user which SQL (`supabase/*.sql`, `supabase/seed/*.sql`) they must run by hand. Never commit `.claude/` or `.env*`.
- **Catalog data:** edit JSON in `supabase/data/`, then run `node scripts/build-seed.mjs` to regenerate `supabase/seed/*.sql` (a big museum is split into `<name>-1.sql`, `-2.sql`, …; the SQL editor rejects large queries, so keep each file under ~800 KB). There is no `seed-all.sql` any more.
- **Louvre:** the catalog, `src/data/louvre/*.json` and the floor plan are generated by `scripts/louvre/` (see its README); do not hand-edit them. The UI is `src/components/LouvreExplorer.tsx`.
- **Local tooling:** there may be no Node on PATH. A Node 22 x64 binary run under Rosetta (`arch -x86_64`) works with the installed Next SWC package.
- **Prado:** `scripts/prado/`; UI `src/components/PradoExplorer.tsx` (rooms only, collapsed, no floors/areas by decision). Room data comes from `research/prado/prado-rooms.json`, collected by the user running `research/prado/collect-rooms.js` in their own browser (the Prado site blocks bots; do not try to bypass it). Rebuild: see `scripts/prado/README.md`. Some rooms were short (paging); re-collect to fill. Don't invent room/floor data.
- **Museum pages:** the Louvre explorer is the north star for every museum; see `AGENTS.md` for the principles (geometry first, orthogonal wing/level filters, never disable chips, sourced data only).
- **Localization:** nine languages (en, zh, fr, es, de, pt, it, ja, ko). UI text lives in `src/lib/i18n.ts` (`strings` for guide pages, `uiStrings` for the rest) and `OPTION_LABELS` in `src/lib/preferences.ts`; museum/place names in `src/data/museumNames.ts`; shared metadata labels in `src/data/factLabels.ts`. Adding UI text means adding it in all nine. Catalog (artwork) text exists only in the languages in the DB; a museum without the visitor's language shows English, while page text stays in the visitor's language. First login is language-only (`LanguageSelect`), then saved to `user_preferences`.
