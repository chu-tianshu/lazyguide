# LazyGuide: notes for Claude

- **Ship workflow:** after finishing a change, commit and push to `origin/main` without asking. Vercel deploys every push to `main`. Then tell the user which SQL (`supabase/*.sql`, `supabase/seed/*.sql`) they must run by hand. Never commit `.claude/` or `.env*`.
- **Catalog data:** edit JSON in `supabase/data/`, then run `node scripts/build-seed.mjs` to regenerate `supabase/seed/*.sql` and `seed-all.sql`.
- **Louvre:** the catalog, `src/data/louvre/*.json` and the floor plan are generated by `scripts/louvre/` (see its README); do not hand-edit them. The UI is `src/components/LouvreExplorer.tsx`.
- **Local tooling:** there may be no Node on PATH. A Node 22 x64 binary run under Rosetta (`arch -x86_64`) works with the installed Next SWC package.
- **Prado:** `scripts/prado/`; UI `src/components/PradoExplorer.tsx` (rooms only, collapsed, no floors/areas by decision). Wikidata places only ~71 works in a hall. The Prado site blocks bots (Cloudflare), so full room data needs `research/prado/collect-rooms.js`, which the user runs in their own browser (resumable) and which writes `prado-rooms.json`; build from that by matching each work's UUID to Wikidata P8905. Not done yet: that JSON has not been collected. Don't invent room/floor data.
